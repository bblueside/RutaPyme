# Bitácora de IA — Feature 1 (Red operativa inicial)

Herramienta: **Claude Code** (modelo Claude Opus), con el arnés `CLAUDE.md`, las skills
`sdd-feature` y `prueba-aceptacion` y los agentes `revisor-reglas` y `trazador-grafos`.
Cómo se organizó el trabajo con IA: [`uso-ia-sdd.md`](uso-ia-sdd.md).

> Cada integrante debe poder explicar cada fila. Si una fila no se entiende, no se entrega.

| # | Decisión o pieza | Herramienta / objetivo de IA | Propuesta recibida | Acepté o rechacé y por qué | Cómo la verifiqué |
|---|------------------|------------------------------|--------------------|----------------------------|-------------------|
| 1 | Framework de la API | Claude Code · elegir cómo exponer la API REST | Usar Flask o FastAPI | **Rechazada.** La guía y el equipo acordaron no usar bibliotecas externas en el backend. Se usó `http.server` de la biblioteca estándar | `requirements.txt` solo tiene NetworkX y matplotlib; el agente `revisor-reglas` confirmó que `backend/` solo importa módulos estándar |
| 2 | Interfaz | Claude Code · elegir tecnología de frontend | Streamlit | **Rechazada.** Es otra biblioteca externa. Se hizo HTML + CSS + JS nativos servidos por el mismo servidor | La interfaz funciona solo con `python main.py`; `app.js` usa `fetch('/api/...')` |
| 3 | Dirección del grafo | Claude Code · modelar la red | Grafo **dirigido** (A→B no implica B→A) | **Aceptada.** Responde la pista del brief: calles de un sentido y costos distintos de ida y vuelta | Escenarios 09 y 10 del script: B no tiene salida hacia A hasta registrarla, y se acepta con otro costo |
| 4 | Estructura principal | Claude Code · comparar representaciones | Lista de adyacencia `{punto: {destino: costo}}` frente a matriz | **Aceptada la lista.** La operación principal es pedir vecinos (O(grado) vs O(V)); la red es dispersa (O(V+E) vs O(V²)) | Tabla de complejidad y traza manual en `modelado.md`, comparada contra `backend/red.py` |
| 5 | Significado del peso | Claude Code · definir el costo | Minutos estimados, siempre > 0 | **Aceptada.** Tiene sentido en el negocio y la Feature 3 necesita pesos positivos | Escenarios 20–24: costo 0, negativo, texto, booleano y entero enorme → 400 |
| 6 | Identificadores | Claude Code · reglas de validación | Normalizar a mayúsculas para que `bod-centro` y `BOD-CENTRO` sean el mismo punto | **Aceptada.** Evita duplicados "invisibles" que confunden al coordinador | Escenarios 03 y 14 |
| 7 | Lazos A→A | Claude Code · reglas de validación | Rechazar un trayecto de un punto hacia sí mismo | **Aceptada.** No representa un movimiento real de pedidos | Escenario 27 |
| 8 | Persistencia | Claude Code · guardar la red | Usar una base de datos SQLite | **Rechazada** por ahora: fuera del alcance del brief. La red vive en memoria y se ofrece una red de ejemplo | Especificación, regla R-08 y sección "Fuera de alcance" |
| 9 | Visualización | Claude Code · dibujar la red | NetworkX con `pyplot` | **Modificada.** Se usa NetworkX con `matplotlib.figure.Figure` (sin `pyplot`), que es seguro con varios hilos; NetworkX solo recibe una copia de la red ya validada | Escenario 35 (PNG válido) e inspección visual de `docs/img/red-ejemplo.png` |
| 10 | Servidor | Claude Code · concurrencia | `HTTPServer` de un solo hilo | **Rechazada.** Un navegador puede dejar conexiones abiertas y congelarlo. Se usó `ThreadingHTTPServer` con un candado sobre la red | Uso de la interfaz con varias peticiones en paralelo (`Promise.all`) sin bloqueos |
| 11 | JSON con `NaN` | Claude Code · revisión de validaciones | `json.loads` acepta `NaN` e `Infinity` por defecto; propuso rechazarlos con `parse_constant` | **Aceptada** | Escenario 26 |
| 12 | Formulario de la interfaz | Claude Code · depuración | Cambiar el campo `name="id"` por `name="identificador"` porque choca con la propiedad `id` del formulario | **Aceptada** | Registro de puntos desde la interfaz (prueba manual, paso 5) |
| 13 | Auditoría antes del PR | Agente `revisor-reglas` · revisar reglas y especificación | Veredicto **"Requiere cambios"**: (a) un costo entero enorme producía error 500; (b) un cliente que no termina de enviar el cuerpo bloqueaba la API; (c) la consulta vacía en la interfaz mostraba un error de JavaScript; (d) el contrato no contemplaba 400 en `GET /api/puntos/{id}` | **Aceptadas las cuatro.** (a) se captura `OverflowError`; (b) el cuerpo se lee antes del candado y hay `timeout` de 10 s; (c) la interfaz valida el campo; (d) se actualizó la especificación | Se agregaron los escenarios 24, 30 y 34. **Con el código anterior fallaban** (500 y "timed out"); con la corrección: 37/37 |
| 14 | Detalles menores de la auditoría | Agente `revisor-reglas` | `escapar()` no escapaba comillas; `OPTIONS` respondía HTML 501 | **Aceptadas.** Se escapan comillas y `OPTIONS` responde 405 en JSON. `HEAD` se dejó igual (no lo usa la interfaz) | Revisión del código y prueba manual |
| 15 | Criterio CA-14 sin prueba automática | Agente `revisor-reglas` | Documentar una prueba manual de la interfaz | **Aceptada** | [`pruebas/prueba_manual_interfaz.md`](../../pruebas/prueba_manual_interfaz.md) |
| 16 | Despliegue | Claude Code · local vs instancia gratuita | Trabajar en local y dejar `render.yaml` listo como opción | **Aceptada.** La guía pide pruebas contra la API local y la demo no depende de internet | Tabla comparativa en `plan.md`; `main.py` lee `HOST` y `PORT` |
